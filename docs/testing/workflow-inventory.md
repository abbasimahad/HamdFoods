## Classification rules

- `COMPLETE`: the routed workflow and its required user-facing lifecycle are implemented; a planned sidebar entry may also be `COMPLETE` when it duplicates an implemented workflow at another route.
- `BACKEND EXISTS / UI INCOMPLETE`: authoritative records/read models exist, but the named dedicated user interface is absent or materially incomplete.
- `PARTIAL`: meaningful pieces of the named workflow exist in both domain/application code and UI, but the end-to-end workflow named by the sidebar is not complete.
- `MISSING`: no dedicated domain aggregate/application workflow/UI exists for the named capability. Adjacent accounting or inventory effects do not make the workflow complete.
